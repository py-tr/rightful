How it works. The agent writes scripts that run in a disposable sandbox holding no credential. Every account change it attempts is refused by the gate and turned into a push to the account owner's phone, naming the action and the account. Only the owner's yes to that exact request lets it through, once. The rightmost column is read from the identity server's own log, not from our software.
Simulated here. The phone (in production: the owner's authenticator app), the people (all fictional), the email inbox (we only show that an email arrived). Cooling-off is shortened to 20 seconds for the demo (production: 60 seconds, 10 minutes for privileged accounts).
What this demo does not claim. That people always read a push carefully (no study we found shows that); that a sandbox is an absolute boundary; that the model is safe. The claim is narrower: without the owner's approval of the exact request, the identity server records no change.
