"Why not just make the approval mandatory inside the reset function?" Because that function runs in the agent's sandbox, so its key would too: anything enforced in the agent's own process is the agent's to skip, forge or leak. The only approval that cannot be skipped is one the agent cannot reach, bound to a key it never holds.

How it works, and what this demo does not claim

The agent writes scripts that run in a disposable sandbox holding no credential. With Keyless, every account change it tries is refused by the gate and turned into a request on the owner's phone that names the action and the account; only the owner's yes to that exact request lets it through, once. In the comparison column the same agent, with the same instructions and the same push tool, decides for itself whether the caller is verified, as in today's ticketing systems and agent frameworks. The rightmost receipt column is read from the identity server's own log with a view-only account, not from our software. Simulated: the phone, the people, the inbox (we only show that an email arrived). The cooling-off is 20 seconds here (production: 60 seconds, 10 minutes for privileged accounts).

Not claimed: that people always read a phone request carefully (we found no study showing it), that a sandbox is an absolute boundary, or that the model is safe. The claim is narrower: without the owner's approval of the exact request, the identity server records no change.
